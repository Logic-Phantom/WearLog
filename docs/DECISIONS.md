## D-016 (2026-10-27) 쇼케이스 화면 중 정책상 그대로 못 만든 부분
- **날씨 숫자**: 쇼케이스의 12°C·비 60% 등은 서버(기상청 프록시) 연결 시에만 표시. 수동 날씨는 라벨 + 정책 구간("추천 기준 13~18°C")으로 표시하고 온도를 지어내지 않음.
- **팔로워/팔로잉 숫자**: 팔로우 기능이 없어 프로필 통계는 실제 로컬 값(내 옷·저장한 코디·게시물). "팔로잉" 탭은 "준비 중" 빈 상태.

- **커뮤니티 게시물**: 서버 미설정 시 쇼케이스 사진으로 만든 샘플 게시물 5개를 "샘플 게시물" 안내와 함께 표시. 하트는 화면 안에서만 바뀌고 저장·전송하지 않음.
- **착용 기록 예시**: 기록이 없을 때만 "예시" 배지와 함께 3줄 표시. DB에 쓰지 않고 통계에 안 들어감.
- **코디추천 세그먼트**: 쇼케이스대로 "날씨 맞춤 | 취향 맞춤"(취향 맞춤 = 날씨 점수 끔). 내 옷만/샘플 포함은 아래 칩으로 이동. 내 옷이 부족하면 샘플 추천을 "샘플" 배지와 함께 보여줌.

## D-020 (2026-10-27) "공유 → WearLog": expo-share-intent 도입, Expo Go 지원 종료
- 결정: `expo-share-intent` 9.0.0(SDK 58용, 2026-10-21 배포)으로 Android 공유 대상·iOS 공유 확장 생성. 받은 사진/링크는 옷 등록 화면으로만 전달하고 저장은 사용자가 누를 때만.
- 대안: 직접 만든 Expo 로컬 모듈 — Android 인텐트·iOS 확장 타깃·App Group을 모두 직접 관리해야 해서 기각. Android `intentFilters`만으로는 공유 파일을 JS에서 읽을 수 없음.

- 리스크: 라이브러리 Android `getFileInfo`가 빈 커서·null MIME을 처리하지 않아, 읽기 권한 없이 공유된 URI에서 앱이 종료됨(실기기에서 셸 인텐트로 재현). 정상 공유(갤러리)는 문제없음. → 2026-10-27 `patches/expo-share-intent+9.0.0.patch`(patch-package, postinstall)로 수정·실기기 확인. 라이브러리 버전을 올릴 때 패치가 여전히 필요한지 확인하고, 필요 없으면 패치 파일 삭제. 업스트림 제보는 아직. 최신 배포본이라 공급망 위험도 있어 설치 전 패키지 내용(설치 스크립트 없음, 네트워크 호출 없음)을 확인함.

## D-021 (2026-10-28) 날씨 추천: "제철 아님" 감점 추가
- 문제: 실기기(10-27)에서 쌀쌀함인데 반팔 티가 상의로 추천됨. 반팔 티 계절 태그(봄·여름)의 "봄"이 쌀쌀함 구간 계절(가을·봄)과 겹쳐 오히려 가산점을 받았음.
- 결정: `BandRule.offSeasons` 추가 — 아이템의 계절 태그가 **모두** 이 목록 안이면 `offSeasonPenalty`(1.5) 감점, 계절 가산점은 주지 않음. 쌀쌀함·추움 = 봄·여름, 매우 추움 = 봄·여름·가을, 선선 = 겨울, 따뜻함 = 가을·겨울, 더움 = 봄·가을·겨울. 셔츠(봄·여름·가을)처럼 걸치는 계절이 있으면 감점 없음.
- 대안: 하위 카테고리(반팔·민소매·쇼츠) 금지 목록 — 직접 등록한 옷은 하위 카테고리가 비어 있어 적용되지 않아 기각. 계절 태그는 사용자도 고르므로 같은 규칙이 내 옷에도 적용됨.

## D-022 (2026-10-28) 저장·착용 코디 유사도 페널티 연결
- 최근 14일(`SIMILAR_OUTFIT_LOOKBACK_DAYS`) 안에 저장했거나 착용한 코디의 아이템 키 집합을 엔진 `recentOutfitSignatures`로 전달. 키 형식은 엔진과 같은 `owned:<id>` / `sample:<templateId>`(`refsSignature`). 같은 조합은 `similarOutfitPenalty`만큼 내려가 "다른 코디"가 먼저 보임. 정확히 같은 조합만 비교(부분 유사도는 아직 아님).

## D-023 (2026-10-28) 샘플 → "내 옷으로 등록": 속성만, 사진은 옮기지 않음
